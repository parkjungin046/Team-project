# 관리자 페이지 사용법

이 관리자 페이지는 두 가지 방식으로 쓸 수 있습니다.

- **로컬 전용 (기본값)**: 본인 컴퓨터에서만 실행. 데이터는 로컬 파일에 저장. 외부에서는 접속 불가.
- **Render 온라인 배포**: 어디서든 브라우저로 접속 가능. 데이터는 PostgreSQL에 저장. "공개" 저장 즉시 실제 웹사이트에 실시간 반영.

아래는 로컬 전용 사용법이고, Render 배포는 맨 아래 [Render에 배포하기](#render에-배포하기) 섹션을 참고하세요.

## 처음 한 번만: 설치

```bash
npm install
```

## 관리자 비밀번호 설정 / 변경

```bash
npm run set-admin-password -- "원하는비밀번호"
```

- 입력한 비밀번호는 어떤 파일에도 평문으로 남지 않습니다.
- `bcrypt`로 되돌릴 수 없게 암호화된 값만 `.env` 파일에 저장됩니다.
- `.env`는 `.gitignore`에 등록되어 있어 GitHub에는 절대 올라가지 않습니다.

## 실행

```bash
npm run admin
```

터미널에 아래처럼 뜨면 정상 실행된 것입니다.

```
✅ 관리자 페이지가 실행되었습니다: http://localhost:4300
```

브라우저에서 `http://localhost:4300` 접속 → 비밀번호 입력 → 프로젝트 등록/수정.

## 프로젝트 등록 → 웹사이트 반영까지

1. 관리자 페이지에서 프로젝트 정보를 입력하고 "공개"를 선택해 저장합니다.
2. 저장 즉시 `data/public-projects.generated.js` 파일이 자동으로 갱신됩니다.
   - 로컬에서 `npx serve .` 등으로 사이트를 보고 있다면 새로고침만으로 바로 확인됩니다.
3. 실제 배포 사이트(GitHub 등)에 반영하려면, 평소처럼 변경 사항을 커밋 & 푸시하면 됩니다.
   ```bash
   git add data/public-projects.generated.js
   git commit -m "프로젝트 추가"
   git push
   ```
4. "초안"으로 저장한 프로젝트는 이 파일에 포함되지 않으므로 실제 웹사이트에는 절대 노출되지 않고,
   관리자 페이지에만 계속 남아 있습니다 (다시 로그인해도 그대로 유지됩니다).

## 보안 설계 요약

- 비밀번호는 bcrypt 해시로만 `.env`에 저장되고, 프론트엔드로 전송되지 않습니다.
- `.env`, `data/projects.json`(초안 포함 원본)은 `.gitignore`로 GitHub 업로드에서 제외됩니다.
- 로그인 세션은 `httpOnly` 세션 쿠키로만 유지되며, **만료 시간을 지정하지 않아** 브라우저를 완전히 닫으면
  자동으로 삭제됩니다 → 다시 열면 항상 새로 로그인해야 합니다.
- 관리자 서버를 재시작할 때마다 세션 암호화 키가 새로 생성되어, 이전 세션은 모두 즉시 무효화됩니다.
- 로그인 실패가 10분 내 5회를 넘으면 일시적으로 잠깁니다.
- 서버는 `127.0.0.1`(로컬)에만 열리며, 같은 네트워크의 다른 기기에서도 접속할 수 없습니다.

## 중복 프로젝트 정리

제목이 같은(공백 차이만 있어도 인식) 프로젝트가 2건 이상이면 관리자 페이지 상단에 경고가 표시됩니다.
남기고 싶은 항목의 "이것만 남기기" 버튼을 누르면 나머지는 삭제되고 하나로 통합됩니다.

## Render에 배포하기

Render에 올리면: 어디서든 브라우저로 관리자 페이지에 접속할 수 있고, "공개"로 저장하는 즉시 실제
웹사이트(정적 사이트)에도 실시간으로 반영됩니다. (로컬 전용 방식은 git push를 해야 반영되지만,
Render 방식은 저장과 동시에 반영됩니다.)

### 1) GitHub에 먼저 push

이 저장소가 GitHub에 올라가 있어야 Render가 코드를 가져갈 수 있습니다. (이미 되어 있다면 생략)

### 2) Render에서 Blueprint로 한 번에 생성

1. [render.com](https://render.com) 가입 (GitHub 계정으로 로그인 가능)
2. 대시보드에서 **New +** → **Blueprint** 선택
3. 이 GitHub 저장소를 연결 → 저장소에 있는 [render.yaml](../render.yaml)을 자동으로 인식합니다
4. **Apply** 를 누르면 아래 2개가 자동으로 만들어집니다.
   - `portfolio-admin` — 관리자 백엔드 웹 서비스 (무료 플랜)
   - `portfolio-admin-db` — PostgreSQL 데이터베이스 (무료 플랜)

### 3) 비밀번호 해시 값 등록 (Render 대시보드에서 직접, 코드에는 절대 넣지 않음)

로컬에서 아래 명령을 실행하면 해시값이 `.env`에 저장되는데, 그 값을 **복사만** 해서 Render에 붙여넣습니다.

```bash
npm run set-admin-password -- "원하는비밀번호"
cat .env   # ADMIN_PASSWORD_HASH=... 값을 복사
```

Render 대시보드 → `portfolio-admin` 서비스 → **Environment** 탭 → `ADMIN_PASSWORD_HASH` 값 붙여넣기 → 저장.
(이 값은 되돌릴 수 없는 해시이므로 노출되어도 원래 비밀번호를 알아낼 수 없습니다. 그래도 Render
대시보드 자체는 본인 계정으로만 로그인되므로 안전합니다.)

### 4) 배포 완료 후 주소 확인

서비스가 배포되면 `https://portfolio-admin-xxxx.onrender.com` 같은 주소가 생깁니다.
이 주소로 접속해서 평소처럼 비밀번호로 로그인하면 됩니다.

### 5) 공개 웹사이트가 이 주소를 실시간으로 읽어가게 연결

[index.html](../index.html)에서 아래 줄을 찾아 Render 주소로 바꿔주세요.

```html
<script>
  window.PORTFOLIO_API_BASE = "https://portfolio-admin-xxxx.onrender.com";
</script>
```

바꾼 뒤 git commit & push 하면, 그 다음부터는 관리자 페이지에서 "공개"로 저장하는 즉시
(재배포 없이도) 웹사이트에 바로 나타납니다.

### 참고 (무료 플랜 한계)

- Render 무료 웹 서비스는 일정 시간 요청이 없으면 잠들어서, 다시 깨어날 때 첫 응답이 몇십 초 걸릴 수 있습니다.
- Render 무료 PostgreSQL은 일정 기간(가입 시점 기준 약 90일) 후 만료되니, 계속 쓰려면 유료 플랜으로
  전환하거나 새 데이터베이스로 마이그레이션이 필요합니다.
- 위 두 가지가 부담되면 지금처럼 로컬 전용 방식을 계속 쓰셔도 전혀 문제 없습니다
  (`window.PORTFOLIO_API_BASE`를 빈 문자열로 두면 자동으로 로컬 전용 방식으로 동작합니다).
